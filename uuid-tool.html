UUID 생성기

버튼 하나로 고유한 UUID(v4)를 즉시 생성해요. 여러 개를 한 번에 만들 수도 있어요.

📖 사용법 보기 ▸
1생성 개수를 정하세요. 1개부터 최대 50개까지 한 번에 만들 수 있어요.
2대문자로 표시하고 싶다면 '대문자로 표시'를 체크하세요.
3'UUID 생성' 버튼을 누르면 즉시 만들어져요.
4각 UUID 옆 '복사' 버튼으로 하나씩, 또는 '전체 복사'로 한 번에 가져다 쓰세요.
💡 이 도구는 UUID v4(무작위 기반) 표준을 사용해요. 데이터베이스 기본키, 세션 ID 등 고유 식별자가 필요한 곳에 바로 사용하실 수 있어요.

이 도구는 무엇을 하나요?

UUID 생성기는 버튼 하나로 고유한 UUID(Universally Unique Identifier, 범용 고유 식별자)를 즉시 만들어주는 도구입니다. UUID v4(무작위 기반) 표준을 사용하며, 한 번에 최대 50개까지 생성할 수 있고 대문자 표시 옵션도 지원합니다. 생성된 UUID는 개별 복사 또는 전체 복사로 바로 가져다 쓸 수 있습니다.

왜 만들었나요?

데이터베이스 설계나 API 개발을 하다 보면 순차적으로 증가하는 숫자 ID 대신, 예측 불가능하고 충돌 위험이 거의 없는 고유 식별자가 필요한 경우가 많습니다. 매번 UUID를 코드로 생성해서 확인하기보다, 필요할 때 즉시 여러 개를 만들어 바로 복사해 쓸 수 있는 가벼운 도구가 있으면 테스트 데이터 준비나 임시 식별자 발급이 훨씬 빨라진다고 생각해 만들게 되었습니다.

이런 상황에 유용해요

  • 데이터베이스 테이블의 기본키(Primary Key)로 사용할 고유 식별자가 필요할 때
  • 테스트 데이터를 여러 개 준비하면서 각각 고유한 ID를 부여하고 싶을 때
  • 세션 ID, 요청 추적 ID(트레이스 ID) 등 임시 식별자가 필요할 때
  • 여러 클라이언트나 기기에서 발급해도 충돌하지 않는 ID 체계가 필요할 때

사용할 때 주의할 점

UUID v4는 무작위성에 기반하기 때문에 이론적으로 충돌 확률이 매우 낮지만(사실상 0에 가까움), 절대적으로 0이라고 보장하지는 않습니다. 극도로 높은 보안이 요구되는 용도(예: 결제 시스템의 유일 거래 ID)라면 데이터베이스 차원의 고유성 제약 조건(UNIQUE 제약)을 함께 적용하는 것이 안전합니다. 또한 UUID는 문자열 형태라 순수 숫자 ID보다 저장 공간을 더 차지하고, 인덱스 성능이 상대적으로 낮을 수 있다는 점도 대규모 시스템 설계 시 고려해야 합니다.

자주 묻는 질문

Q. UUID가 겹칠 가능성은 없나요?
UUID v4는 122비트의 무작위 값을 사용하여, 실제로 충돌할 확률은 사실상 무시해도 될 만큼 낮습니다. 매초 10억 개씩 생성해도 충돌 가능성은 극히 희박합니다.
Q. 생성된 UUID가 저장되나요?
아니요. 이 도구는 브라우저 안에서만 UUID를 생성하며, 생성된 값은 서버로 전송되거나 저장되지 않습니다.
Q. UUID 버전(v1, v4 등)은 뭐가 다른가요?
v1은 타임스탬프와 기기 정보를 기반으로, v4는 완전한 무작위 값을 기반으로 생성됩니다. 이 도구는 개인정보 노출 위험이 없는 v4 방식을 사용합니다.
